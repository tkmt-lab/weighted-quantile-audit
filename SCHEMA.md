# Witness schema v1 (producer/checker interface)

Successful document has schema="weighted-quantile-audit/v1", status="OK", nominal_input and binary_input (canonical rational strings x,w,p), hex_input (x,w arrays and p float.hex strings), certificates={nominal:{boundary_average:C,inverted_cdf:C},binary:{boundary_average:C,inverted_cdf:C}}.
C={kind:"point"|"tie",left:q,right:q|null,L:q,U:q,target:q,W:q,value:q}. For either definition select first support whose cumulative weight >= target. point means L<target<U and right=null; tie means target=U, right=next support. boundary_average tie value=(left+right)/2; inverted_cdf tie value=left. Both certs retain tie kind.

axes={definition_difference:bool,input_rounding_changes_value:bool,implementation_value_mismatch:bool}. Compare binary boundary_average vs inverted_cdf exact; nominal vs binary boundary_average exact; correctly rounded binary boundary_average vs actual observed hex respectively.
input_rounding={changed_fields:["x[0]",...,"w[0]",...,"p"]} in this order, only where exact values change.

observed={value_hex:str,expected_hex:str,branch_candidates:[str],branch_identification:str}. All sorted distinct binary support points are candidates "point:"+canonical-rational; consecutive support means are candidates "tie:"+a+","+b, with the *float addition then division* midpoint. Keep candidates whose float values equal actual output. branch_identification is sole candidate or BRANCH_UNKNOWN. This is inference from value, not measured trace.

arithmetic={support:[q],cumulative_hex:[str],target_hex:str,selected_index:int,gap_hex:str,tolerance_hex:float(1e-10).hex(),tolerance_hit:bool,has_successor:bool,cumulative_exact:bool,target_exact:bool,predicted_hex:str,matches_observed:bool}. support is sorted unique binary input values. Diagnostics reproduce pandas sum over equal values then numpy cumsum, p*last cumulative, left searchsorted; gap is abs(float target-float cumulative[j]); tolerance strict less than float(1e-10), mean iff hit and successor, else point. cumulative_exact compares every saved cumulative to direct rational sum of binary weights for x<=support; target_exact compares saved target to p*exact W. Checker validates internal arithmetic consistency but cannot authenticate pandas group sums without observation replay.

implementation_diagnosis is NO_VALUE_MISMATCH when no output mismatch; otherwise TOLERANCE_ONLY_WITNESS if cumulative_exact and target_exact and nonzero gap and tolerance_hit and has_successor and matches_observed and branch_identification != BRANCH_UNKNOWN; otherwise ARITHMETIC_ROUNDING_PRESENT if not (cumulative_exact and target_exact); otherwise UNRESOLVED. This is a sufficient condition, not exhaustive attribution.

environment includes python, distributions, weightstats_sha256. The producer accepts Python 3.12; replay requires exact equality of the saved python string and the current Python version, including the patch number. Missing or changed python metadata is rejected, as are mismatched distribution versions and module hashes. source includes audit_sha256,checker_sha256. verification={valid:bool,...} is output of stdlib checker in separate process; checker ignores this self-report and recomputes. Unsupported documents have status="UNSUPPORTED",reason:string; environment problems status="ENVIRONMENT_UNSUPPORTED"; malformed JSON status="INVALID_JSON"; checker rejects status != OK. CLI exit codes: 0 OK,2 unsupported/invalid input,3 environment,4 internal or recheck failure. Input and witness byte limits are separate (64KiB, 2MiB).
